# Template Edit/Delete Management Plan

## Overview

`/amidakuji` の既存テンプレート利用フローを拡張し、既存テンプレートを抽選に使うだけでなく、その場で編集・削除できるようにする。  
既存のテンプレート共有モデルは維持しつつ、編集・削除は誤操作防止と権限制御を前提に実装する。

## Scope

- `/amidakuji` の既存テンプレート一覧から選択したテンプレートに対して、次の操作を提供する。
  - 抽選へ進む
  - 編集する
  - 削除する
- 編集対象は次の2項目に限定する。
  - テンプレート名
  - 選択肢一覧
- 削除時には明示的な確認ステップを挟む。
- 編集・削除の権限は次のいずれかを満たすユーザーに限定する。
  - テンプレート作成者
  - `Manage Guild` 権限を持つメンバー
- Persistence / Application / Discord UI の各レイヤに update / delete 導線を追加する。
- guide / reference / README のうち、利用者が触れる導線説明に影響する箇所を更新する。

## Non-Goals

- 編集・削除用の別 slash command を追加すること
- 選択肢の並び替え機能を追加すること
- 編集履歴、削除履歴、監査ログを保持すること
- 作成者の変更やテンプレート所有権移譲をサポートすること
- last used スナップショット自体を削除時に消去すること

## Requirements

- **Functional**:
  - 既存テンプレート一覧でテンプレート選択後、抽選前の中間画面を表示し、抽選・編集・削除を選べること
  - 編集開始時には現在のテンプレート名と選択肢を初期値として表示すること
  - 編集時は空白のみのタイトルを拒否し、空の選択肢を除去したうえで 1 件以上の選択肢を必須とすること
  - 編集後に同一 guild 内で重複タイトルになる場合は保存を拒否し、既存の重複エラーと同等のメッセージを返すこと
  - 編集成功後は更新済みテンプレートを選択済みの状態として参加者選択画面へ進めること
  - 削除時は確認 UI を経由し、確認後にテンプレートを削除すること
  - 削除成功後はテンプレート一覧へ戻し、対象が一覧から消えていることを示すこと
  - 削除対象テンプレートが `last used` に紐づいていた場合でも、DB の `on delete set null` により `source_template_id` のみを外し、スナップショット利用は継続できること
  - 編集・削除対象が途中で消失した場合は `テンプレートが存在しません。` を返すこと
  - 編集・削除の権限を持たないユーザーには操作を拒否し、抽選利用のみ可能とすること
- **Non-Functional**:
  - 既存の ephemeral ベースの UX を維持し、他ユーザーに管理操作の途中状態を見せないこと
  - 既存の `TemplateBuilderView` を可能な範囲で再利用し、作成と編集で UI 挙動を過度に分岐させないこと
  - DB スキーマ変更は原則行わず、既存マイグレーションの制約と外部キー挙動を活用すること
  - 例外メッセージとログ粒度は既存方針に合わせ、予期しない例外では汎用エラーにフォールバックすること

## Tasks

- `GuildTemplateRepository` に次の API を追加する。
  - `get_by_id(guild_id, template_id)`
  - `update(template_id, guild_id, title, options)`
  - `delete(template_id, guild_id)`
- `AmidakujiService` にテンプレート更新・削除用のメソッドを追加し、入力正規化と業務ルールを集約する。
- Discord UI にテンプレート管理中間画面を追加し、抽選・編集・削除の分岐を実装する。
- 既存のテンプレートビルダーを編集モード対応させ、初期値表示と保存先切り替えを行えるようにする。
- 削除確認用 View を追加し、誤操作防止を行う。
- 権限制御を UI で判定し、非権限者には編集・削除ボタンを表示しないか、押下時に拒否する。
- guide / reference / README を更新し、新しい導線と制約を記述する。

## Test Plan

- Repository / Service レイヤで次を検証する。
  - タイトル空文字、空選択肢、空白選択肢混在の正規化
  - 更新時の重複タイトル検知
  - 存在しないテンプレート更新・削除時のエラー
- UI レイヤで次を検証する。
  - 既存テンプレート選択後に管理画面へ遷移すること
  - 編集成功後に参加者選択画面へ進むこと
  - 削除確認後に一覧へ戻ること
  - 権限なしユーザーの編集・削除が拒否されること
- 回帰観点として次を確認する。
  - 既存の「既存テンプレートを使う」「新規作成する」「最後に使ったテンプレートを使う」フローが壊れていないこと
  - 削除済みテンプレートを参照していた `last used` から抽選できること

## Deployment / Rollout

- DB マイグレーションは追加しない前提で実装する。
- デプロイ後は Discord 上で次を手動確認する。
  - 既存テンプレート選択後に管理画面が表示される
  - 作成者が編集・削除できる
  - 非作成者かつ非管理者は編集・削除できない
  - 削除済みテンプレートでも `last used` から抽選できる
- 問題発生時は、管理導線を含む変更をロールバックし、既存の抽選フローへ戻す。
